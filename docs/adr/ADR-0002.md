# ADR-0002 · 内容 manifest 与「路径即 id」

- 状态：Accepted（已落地，P0/P1）
- 日期：2026-10-14
- 关联：ARCHITECTURE §3.1、§11；[ADR-0004](ADR-0004.md)

## 上下文（Context）

在线 VitePress 与离线单文件 HTML 是同一份内容的两种形态，历史上两者各自解析 Markdown，存在漂移风险。还需要：

- 一份「内容清单」支撑离线对账、学习数据按章登记、未来发布制品（release.json）；
- 保证**已发布 URL 永不变**（重构只能 `git mv`，不能改章节路径）；
- 不接受给 140 章逐章回填稳定 id / 审核状态 / 来源（ARCHITECTURE §14 明确不做）。

## 决策（Decision）

由 `@hw/content-core`（TS，`buildManifest`）从 `SUMMARY.md` + 各章 frontmatter + 磁盘扫描生成 `content-manifest.json`：

```ts
ContentManifest { appId, revision, docs[] }
ContentDoc {
  id        // = 相对路径（如 opamp/inverting-amplifier.md），不另造稳定 id
  path      // = id
  url       // clean URL（/opamp/inverting-amplifier）
  title, part, order, tags[], difficulty?, images[], checksum
}
```

- **路径即 id**：`id=path=相对 docs 的路径`，`url` 由路径派生 clean URL。不新增、不回填 `id/status/sources` 字段，新字段（如 difficulty）可选。
- `revision = sha256-<overallChecksum 前16位>`，由「id + 每章文件字节 checksum」聚合；内容改一个字节，revision 即变。
- 生成器内强校验：SUMMARY↔磁盘双向一致、id/url 唯一、缺章/孤儿即非零退出。
- 冻结两份入库快照作为回归基准：
  - `tests/routes.snapshot.json`：全部已发布 clean URL（141 条，含首页 `/`）；
  - `tests/manifest.snapshot.json`：docCount / titles / imageTotal / svgCount / grounds / overallChecksum 指纹。
- 快照由 `run_quality.py` 比对；出现删除或变更即失败。

## 备选方案（Alternatives）

- 给每章手写稳定 id 与状态：能做内容重排，但要批量回填 140 章且增加维护面，本期明确否决（backlog B2–B5）。
- 以 frontmatter slug 作 id：与路径两套真值，易不一致，否决。

## 后果（Consequences）

- 章节文件可被 `git mv` 而不破坏内容指纹；**只要路径不变，URL 永不变**。
- 任何改路径/删章/改 clean URL 的动作都会让路由快照失败 → 属于破坏性变更，必须先写 ADR 并人工更新快照（见 CONTRIBUTING）。
- 学习数据、收藏、笔记都以相对路径 id 为键，因此章节文件不可随意改名（改名=新章，旧数据进 tombstone，见 [ADR-0003](ADR-0003.md)）。
- TS 与 Python 两套解析必须保持逐字一致（parity），见 [ADR-0004](ADR-0004.md)。
