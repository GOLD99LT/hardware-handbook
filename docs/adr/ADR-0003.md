# ADR-0003 · 学习数据仓储化与 appId 隔离

- 状态：Accepted（已落地，P1/P2，含浏览器迁移实测）
- 日期：2026-10-14
- 关联：ARCHITECTURE §5、§14.3；[ADR-0002](ADR-0002.md)

## 上下文（Context）

学习功能（在学/已学、收藏、章末笔记、进度总览、导入导出）最初由主题组件直接读写**全局唯一** localStorage 键 `hh.v1.learning`。Monorepo 多专项后：

- 不同 app 的数据会互相污染；
- 组件直接碰 localStorage 不利于 SSR、测试与未来换存储；
- 数据格式演进（旧笔记是纯字符串，需要带更新时间）与跨内容版本导入（旧版已删/改名的章）需要明确语义。

## 决策（Decision）

在 `@hw/learning` 提供与框架无关的仓储接口 `LearningRepository`（UI 只依赖接口，不直接碰 localStorage）：

- 工厂：`createLearningRepository({ appId, totalChapters, contentRevision?, storage? })`，内部 vue `reactive` 状态；存储解析顺序为注入 `storage` → 浏览器 `localStorage` → 内存 Map（SSR/Node 不崩、不持久化）。
- **按 appId 隔离**：新键 `hb.v1.<appId>.learning`（handbook 为 `hb.v1.handbook.learning`）；持久化形态 `{schemaVersion:1, appId, progress, favorites, notes}`。
- **一次性迁移且保留旧键**：新键缺失而旧 `hh.v1.learning`（`version:1`）存在时，迁移旧数据；旧笔记 `string` 升级为 `{text, updatedAt}`；**不删除旧键**，保证回退不丢数据。
- **导出**：`export()` 返回 `{schemaVersion, appId, contentRevision, exportedAt, progress, favorites, notes}`，`contentRevision` 取入参 > 工厂配置 > `'unknown'`。
- **导入**：`importData(data, 'merge'|'replace')`；校验 appId 与 `schemaVersion===1`、枚举/布尔/笔记结构、单条笔记 ≤100k、笔记总计 ≤5MB；`merge` 不擦未提供项，`replace` 清空后只写已知章。
- **未知章节 tombstone**：维护 `knownIds`（启动从已存数据播种，app 渲染目录时逐章 `getChapter(id)` 注册全量现行章）；导入里不在已知集合的 id 进 `tombstones[]`，**不落库、不计完成率**。
- 本版**继续用 localStorage，不引入 IndexedDB**（ARCHITECTURE §14.3）。

## 备选方案（Alternatives）

- IndexedDB：容量更大、异步，但当前数据量极小，引入异步 API 与复杂度不划算，否决（backlog B6）。
- 各 app 共用一个键、加 appId 前缀字段：单文件易坏、清理与迁移困难，否决。
- 迁移后删除旧键：回退到旧版会丢数据，否决。

## 后果（Consequences）

- 多专项数据互不串扰；旧用户升级不丢数据，旧版回退也安全。
- 章节 id 是相对路径，**改文件名即视为新章**，旧记录会被判定为 tombstone（与 [ADR-0002](ADR-0002.md) 一致）。
- 每个 app 必须在启动时注册全量已知章（`catalog.entries.forEach(e => repository.getChapter(e.id))`），否则未访问过的现行章会被误判为未知。
- 验证：`node packages/learning/test/learning.test.ts` 40 项；并在真实浏览器注入旧键实测（新键写入/旧键保留/字段迁移/0 console 错误）。
